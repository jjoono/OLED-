## `tandem_blue_pep_oled.svg`

Tandem blue PEP-OLED 소자 구조 모식도 (아이소메트릭 분해도).
순수 벡터 SVG이므로 해상도 제한이 없고, 논문/발표자료에 그대로 삽입할 수 있습니다.

- 캔버스: 440 x 520 (viewBox 동일) — 어떤 배율로도 깨지지 않습니다.
- 층 구성 (아래 → 위): ITO/Ag/ITO anode · Polaritonic HTL · Blue EML · CGL ·
  Blue EML · Polaritonic ETL · Ag/Al/Liq cathode
- 발광은 두 EML 유닛 바깥쪽 계면(HTL 위, ETL 아래)에서 나오는 것으로 표현했습니다.

### 편집 방법

| 프로그램 | 비고 |
|---|---|
| **Inkscape** (무료, Win/Mac/Linux) | SVG가 네이티브 포맷이라 손실 없이 열리고 저장됩니다. 가장 권장 |
| **Adobe Illustrator** | 열 때 "Convert to CSS / Use system fonts" 대신 **Cascading Style Sheets 유지** 옵션을 쓰면 그라디언트가 보존됩니다 |
| **Affinity Designer / Figma** | 그라디언트·블러 대부분 그대로 들어옵니다 |
| **웹 브라우저** | 보기 전용 (파일을 드래그해서 열기) |
| **텍스트 에디터** | SVG는 XML이라 색상 코드나 라벨을 직접 고칠 수 있습니다 |

SVG 안의 주요 그룹에 id를 달아두었으므로 레이어 패널에서 바로 찾을 수 있습니다:

## `trans_scale_simulation.svg`

Trans-scale 광학 시뮬레이션 개념도 — 컷어웨이(cut-away) 아이소메트릭.
소자 앞모서리를 사각으로 잘라내어 단면을 드러내고, 그 단면 위에 물리를 그렸습니다.

- 캔버스: 1020 x 565
- 층 구성 (위 → 아래): Metal cathode · OLED · (ITO anode) · Glass ·
  Outcoupling structure (아랫면에 마이크로렌즈 어레이)
- 단면 위 물리 표현
  - **파동광학 영역**: 쌍극자 방사 로브 2개 + 쌍극자 모멘트 화살표 + 퍼져나가는 파면
  - **기하광학 영역**: 유리를 가로지르는 광선, 원거리장 세기 분포(반구 극좌표 + 적색 로브),
    산란 입자와 산란 경로, 마이크로렌즈를 통한 적색 추출광
- 오른쪽: 두 영역을 묶는 브레이스와 노란 점선 패널

레이어 패널에서 찾을 수 있는 id: `layer-Cath`, `layer-Oled`, `layer-Ito`,
`layer-Glass`, `layer-Out`.

|---|---|
| `EX, EY` / `DX, DY` | 아이소메트릭 투영 벡터 (보는 각도) |

## `outcoupling_roundtrip.svg`

그림 1(a) — 외부 광추출 구조가 부착된 OLED에서 빛이 소자와 공기 사이를

- 원본과 달리 `⋮` 로 끊지 않고, **금속 음극부터 마이크로렌즈까지 한 장에** 그렸습니다.

## `emitting_area.svg`

저손실 설계 소자와 일반 소자의 **발광 면적 · 밝기** 비교. 아이소메트릭 스택 2개.

- 캔버스: 1200 x 492
- 왼쪽 = 일반 소자, 오른쪽 = 디자인 룰 적용 (Fig.1(a)와 좌우 순서를 맞춤)

### 발광 영역 크기를 눈대중으로 정하지 않았습니다

Fig.1(a)와 **같은 왕복 손실 모델**에서 두 수치를 유도해 그대로 씁니다.

```
rho = (1-eta) * R_metal * T_TCO^2     한 왕복당 살아남는 비율
Lam = 1 / ln(1/rho)                   측방 확산 길이
tot = eta / (1-rho)                   최종적으로 빠져나오는 총 광량
```

| | rho | 확산 길이 | 총 추출광 |
|---|---|---|---|
| 일반 소자 (2D 그림) | 0.408 | 1.12 step | 51 % |
| 일반 소자 (3D 렌더) | 0.507 | 1.47 step | 61 % |
| 디자인 룰 | 0.679 | 2.58 step | 94 % |

→ **헤일로 길이 = 확산 길이 비**, **발광 밝기 = 총 추출광 비** 로 대응시켰습니다.

3D 렌더는 일반 소자를 조금 덜 가혹하게(R 0.82 / T 0.94) 잡아 두 패널의 차이가
**1.75× / 1.54×** 입니다. 2D 그림(Fig.1a)의 2.32× / 1.84× 는 메커니즘을 또렷이
보여주려고 대비를 세게 준 값이고, 3D 쪽은 두 소자가 나란히 비교되는 그림이라
차이를 완만하게 두었습니다. 같게 맞추려면 `LAM_C, TOT_C = model(...)` 한 줄의
손실값만 Fig.1a 와 동일하게 바꾸면 됩니다.
(Fig.1(a)의 49 % / 74 % 는 왕복 4회까지만 센 값, 위 51 % / 94 % 는 무한 합계입니다.)

발광은 표면 위의 **원**이므로, 등방성 확산이 아이소메트릭 평면에서 타원으로
보이도록 radial gradient에 `gradientTransform` 으로 같은 투영 기저를 실었습니다.
손으로 타원을 그린 것이 아닙니다.

```bash
python3 figures/make_emitting_area_figure.py
```

팔레트는 `make_roundtrip_figure.py` 에서 import 하므로 Fig.1(a)와 색이 어긋나지
않습니다.

## 소자 적층 구조 — `device_stacks.pptx`, `device_stack_electrode.pptx`

`make_stack_pptx.py` 가 만듭니다. 두 소자의 층 구성을 아이소메트릭 블록으로 쌓은
그림이고, **파워포인트 네이티브 도형 102개, 그룹 0개, 이미지 0개** 입니다. 층 하나를
클릭해서 색·이름·두께를 바로 고칠 수 있습니다.

| 소자 | 아래 → 위 |
|---|---|
| Ag reflector + MLA film | Glass+MLA / ITO / HATCN:TAPC / TCTA / EML / B3PyMPM / B3PyMPM:Cs₂CO₃ / Ag / Nanolaminate / Parylene-C / MoOx+Ag reflector |
| DBR + MLA substrate | MLA substrate / IZO / TAPC:HAT-CN / TCTA / EML / B3PyMPM / Al:Liq / DBR |
| Bottom-emitting OLED (`device_stack_electrode.pptx`) | Glass(n=1.77) / Transparent electrode / HTL 200 / EML 20 / ETL 200 / Ag 100 |

- **한 층에 두 줄짜리 라벨**을 줄 수 있습니다. 이름에 `\n` 을 넣으면 두번째 줄이
  작은 빨간 글씨로 아래에 붙습니다 — 실현 방법이 여러 가지인 층을 위한 것입니다
  (예: `Transparent electrode` + `ITO 50 nm or Ag 10 nm`).
- **세로 배치는 가장 높은 스택을 따라갑니다** (`figure()`). 11층짜리에 맞춘 고정
  베이스라인에 6층짜리를 올리면 제목만 빈 슬라이드 꼭대기에 덩그러니 남습니다.
- **층 목록이 곧 그림입니다.** `STACK_A`, `STACK_B` 리스트를 고치면 블록과 라벨,
  리더선이 같이 따라옵니다. 튜플은 `(라벨, 색, 두께, 라벨색)` 이고 순서는 **아래에서
  위** — 소자를 쌓는 순서 그대로입니다.
- **DBR** 은 `fill=None` 으로 두면 `DBR_PAIRS` 쌍의 고/저굴절 층으로 자동으로
  나뉘어 그려집니다. 원본 그림의 줄무늬 띠와 같은 뜻입니다.
- 두께 숫자(`[150]` 등)는 라벨의 일부입니다. 블록 두께는 **가독성 기준**이지 실제
  비율이 아닙니다 — Parylene-C 3000 nm 를 비율대로 그리면 나머지가 안 보입니다.
- 아이소메트릭은 `EX, EY = 0.866, 0.5`. 층 하나당 면 세 개(윗면·오른쪽·앞면)를
  그리고, 윗면은 맨 위 층에만 그립니다. 밝기는 `shade()` 로 1.00 / 0.86 / 0.70.
- 아래첨자(Cs₂CO₃ 등)는 유니코드가 아니라 **진짜 파워포인트 아래첨자 런**입니다
  (`baseline="-25000"`). 폰트를 바꿔도 깨지지 않고 편집도 됩니다.
- **기판 아랫면은 마이크로렌즈 어레이**입니다 (`lens_bottom=True`, 맨 아래 층에만).
  아이소메트릭에서 아랫면 자체는 절대 안 보이므로, **보이는 아래 모서리 두 개를
  반원으로 물결지게** 그립니다 — 렌즈 어레이의 단면이 실제로 그 모양입니다.
  `MLA_PITCH` 로 렌즈 간격을 조절하고, 피치는 모서리 길이를 정확히 나누도록
  자동 보정되어 양쪽 모서리가 잘린 렌즈로 끝나지 않습니다.
- 발광 화살표는 블록의 **보이는 아래 모서리 두 개**에서, 렌즈 깊이만큼 아래에서
  출발합니다. 아랫면 중심에서 쏘면 스택 한가운데에서 빛이 나오는 것처럼 보이고,
  렌즈 깊이를 빼먹으면 화살표가 렌즈 안에서 시작합니다.

```bash
python3 figures/make_stack_pptx.py        # -> figures/device_stacks.pptx
```

### Blender 버전 — `emitting_area_render.blend`

같은 비교를 실제 3D 렌더로 만든 Blender 4.0 파일입니다. 회색 스튜디오 바닥 위에
소자 스택 두 개, 각 상면 중앙에 불이 들어온 원 하나와 그 위로 낮게 깔리는 빛 안개(볼륨) 콘.

- **발광 영역의 반지름 = 확산 길이 비(2.32×)**, **발광·안개 세기 = 총 추출광 비(1.84×)**
  — 2D 그림과 같은 손실 모델에서 나온 값을 그대로 씁니다.
- **발광 프로파일 = 구동된 둥근 픽셀 + 그 바깥의 확산 헤일로**입니다.

  ```
  r <= PIX_R :  1                          픽셀 자체 (평탄)
  r >  PIX_R :  exp(-(r - PIX_R) / Λ)      옆으로 새어나가 나중에 빠져나온 빛
  ```

  중심이 뾰족한 지수 감쇠가 아니라 **평탄한 코어**를 두는 것이 핵심입니다.
  그래야 "가운데가 제일 밝은 얼룩"이 아니라 "픽셀 하나가 켜졌다"로 읽힙니다.
  `PIX_R` 로 픽셀 크기, `LAM_REF` 로 번지는 거리를 조절합니다.
  프로파일은 `radial_falloff()` 한 곳에서만 정의됩니다.
- 빛 안개는 `Light haze (...)` 콘의 Principled Volume. 높이에 따라 옅어지고
  콘 벽 쪽으로 부드럽게 사라집니다. 밀도·발광은 재질의 마지막 두 `Multiply` 노드.
- **더 밝게 하려면 콘을 높이지 말고 넓고 진하게** 하십시오. AgX 뷰 변환 때문에
  코어 밝기는 이미 천장에 닿아 있어서(피크 초록값이 거의 안 변합니다), 실제로
  "밝아 보이는" 것은 글로우의 면적과 헤일로입니다. 반대로 콘을 높이면 이 시점에서
  슬래브 뒤쪽 모서리 위로 솟아올라, 표면에서 빠져나오는 빛이 아니라 소자 위에 뜬
  초록 덩어리로 보입니다.

#### 공기 중으로 퍼지는 빛의 모양

발광 픽셀을 중심으로 한 **구면 좌표 기준의 버스트**입니다. 원기둥(시준된 제트)도,
둥근 구름도 아닙니다.

```
r'    = max(0, r - PIX_R)           발광 원의 가장자리 기준
d     = hypot(r', z)                공기 중 이동 거리
theta = atan2(z, r')                고도각, 0이 수평 / pi/2 가 수직
f     = exp(-d / fall)
        * (LOBE_GRAZE + (1 - LOBE_GRAZE) * sin(theta))
        * (1 + FAN_AMP * cos(FAN_N * theta))
        * (1 + SHAFT_AMP * cos(SHAFT_N * phi) * ramp(r))
        * (1 - (d / LOBE_R)^4)
```

- **고도각 리플(`FAN_AMP`, `FAN_N`)이 핵심입니다.** theta 로 변조하면 겹겹의 원뿔이
  되고, **원뿔을 옆에서 보면 픽셀에서 뻗어나가는 직선 한 쌍으로 투영됩니다.** 그래서
  부드러운 볼륨인 채로 부채꼴로 퍼지는 빛으로 읽힙니다 — 선을 그어 붙인 빔이 아니라.
- **`LOBE_GRAZE` 는 절대 0이 되면 안 됩니다.** cos(theta) 만으로 가중하면 표면에서
  값이 0이라, 빛이 필름 한참 위에서야 켜지면서 소자 위에 뜬 공처럼 보입니다.
- 돔은 패널 밖으로 삐져나와도 됩니다. 실루엣에서 문제를 일으키는 건 **발광 면**이지
  공기 중 볼륨이 아닙니다.
- `fall` 은 소자마다 다릅니다(`0.55 + 0.45*lam/LAM_REF`). 밝은 쪽이 더 멀리 갑니다.

#### 실루엣에서 빛이 끊겨 보이던 문제

소자 뒷모서리(실루엣)를 지나는 순간 글로우가 진한 초록 → 흐린 초록으로 **딱 끊겼습니다.**
로브 모양 문제가 아니라 **컴포지터 문제**였습니다.

- 예전 컴포지터는 알파를 픽셀의 **채널 최댓값**에서 다시 만들었습니다. 그때의 안개는
  거의 순수 발광이라 알파가 없다시피 했기 때문에 쓴 우회책인데, **씬이 바뀌었는데도
  그대로 남아 있었습니다.** 지금 로브는 산란 밀도가 있어서 Cycles가 실제로 0.32~0.42의
  알파를 내줍니다.
- 그 우회책은 투명 배경 쪽 픽셀만 알파 1로 고정하고 색을 최대 채도로 정규화합니다.
  슬래브 앞쪽은 렌더가 불투명이라 원래의 흐린 색 그대로고요. 그래서 실루엣을 경계로
  두 처리가 갈렸습니다. **측정값: 경계 위 초록도 82, 아래 38.**
- 컴포지터를 끄고 같은 씬을 렌더하면 양쪽 다 17이었습니다. 이걸로 원인이 로브가 아니라
  컴포지터라는 게 확정됐습니다.

지금은 **렌더가 내준 알파로 나눕니다** — 프리멀티플라이드 → 스트레이트 변환 그 자체라
경계가 생길 수 없습니다. 대신 정직한 알파로 가면 **흰 종이 위에서 글로우가 흐려집니다**
(30% 불투명한 초록 안개를 흰색에 올리면 대부분 흰색입니다). 그래서 밝기는 컴포지터에서
속이지 않고 **로브를 실제로 불투명하게** 만들어서 얻습니다 — `LOBE_DENS` 를 올리고
`HAZE_SCATTER`(산란 알베도)는 낮춰서, 불투명도는 흡수에서 색은 발광에서 나오게 합니다.
산란 알베도를 높이면 흰 키 라이트가 투과하면서 플룸이 회색으로 뜹니다.

측정: 경계 위/아래 초록도 67.4 / 68.1 (단차 0.7).

### 씬에 담긴 것

참고한 Nature 계열 소자 모식도들처럼, "무엇을 보는 그림인지"가 그림 안에서
읽히도록 다음을 담았습니다.

| 요소 | 오브젝트 / 함수 | 역할 |
|---|---|---|
| 7층 스택 | `LAYERS` | Al / ETL / EML / HTL / ITO / Glass / Outcoupling structure. 층마다 고유색 |
| 층 라벨 | `stack_label()` | 앞면에 3D 텍스트. Al 층만 밝은 잉크(대비) |
| 마이크로렌즈 | `lens_array()` | 육각 배열 구면 캡. **발광도 여기서 납니다** |
| 캡 사이 필름 | `Lit film (...)` 원판 | 육각 배열의 삼각 구멍을 메웁니다 |
| 빛 안개 | `haze_material()` | 상면에 낮게 깔리는 블룸 |

층은 굴절(transmission)이 아니라 **알파 블렌딩**입니다. Cycles에서 진짜 투과는
뒤에 있는 것을 오히려 가리고 비용도 큽니다.

**발광체는 두 개뿐이고, 둘 다 평평하거나 상면에만 있습니다** — 렌즈 캡
(`LENS_EMIT_FRAC`)과 캡 사이 구멍을 메우는 원판(`GAP_EMIT_FRAC`). 육각 배열은
렌즈 세 개가 만나는 곳마다 작은 구멍이 남는데, 캡만 빛나면 그 구멍이 전부 회색
쐐기로 남아서 원이 아니라 쐐기밭으로 보입니다.

가장자리에 초록 톱니가 생기는 인공물을 네 번 다르게 고쳐 봤는데, 원인은 두
가지였습니다.

1. **이웃 소자의 조명** — 한쪽 소자의 글로우가 건너편 소자의 가까운 모서리를
   물들입니다. 하필 그 모서리는 자기 발광이 가장 약한 곳이라 "없던 빛이 생긴"
   것처럼 보입니다. 모든 발광체에 `no_bounce()`(카메라 외 모든 광선에 비가시).
2. **수직면을 가진 발광체** — 필름 박스 자체를 발광시키면 옆면도 빛납니다.
   클로즈업 카메라는 슬래브의 옆면을 보기 때문에 모서리를 따라 초록 얼룩이
   생기고, 프로파일은 x·y 반경 함수라 아무리 손봐도 없앨 수 없습니다.
   법선(`N.z`)으로 막으면 옆면은 해결되지만 캡이 망가집니다(캡은 꼭대기를 빼면
   법선이 다 기울어져 있어서, 밝은 바닥에 박힌 어두운 점이 됩니다).
   그래서 구멍 메우기는 **평평한 원판**이 맡습니다 — 옆면이 아예 없습니다.

원판 반지름은 `CUT_R` 로, 발광이 정확히 0이 되는 반지름과 같습니다. 그래서
원판의 테두리가 보이지 않고, 패널 가장자리(실루엣)에도 닿지 않습니다.

```
프로파일 = exp(-(r - PIX_R) / Λ) · (1 - (r / CUT_R)^WIN_P)
```

`WIN_P` 가 8로 큰 이유는, 창이 `CUT_R` 근처까지 거의 1이어서 두 소자의 확산비를
건드리지 않게 하기 위해서입니다.

- **발광 색** — 스크립트 상단 `GLOW` (선형 RGB, 기본 `(0.06, 1.0, 0.30)` = 쨍한 초록).
  안개가 산란시키는 색은 `HAZE_SCATTER` 로 따로 두어, 흰 조명이 안개에 반사될 때
  너무 진해지지 않게 했습니다. 색을 바꾸면 두 상수만 고치면 됩니다.
- **마이크로렌즈 어레이 (실제 지오메트리)** — 광추출 필름 위에 구면 캡을
  **육각(삼각) 격자**로 깔았습니다. 행 간격 `pitch*sqrt(3)/2`, 행마다 반 피치씩
  어긋나는 실제 MLA 배열입니다. 소자당 201개, 하나의 메시로 합쳐져 있습니다
  (`Micro-lens array (...)`).

  | 상수 | 뜻 |
  |---|---|
  | `LENS_PITCH` | 렌즈 중심 간격 (0.125 → 가로 16개) |
  | `LENS_FILL` | 렌즈 반지름 / 반 피치. 1.0 이면 서로 맞닿음 |
  | `LENS_SINK` | 캡이 필름에 잠기는 깊이 (반지름 대비). 반구가 아니라 캡으로 보이게 함 |
  | `LENS_SEGS`, `LENS_RINGS` | 돔 하나의 분할 수 |

  렌즈 재질만 `shadow_through=False` 입니다. 다른 투과 층들은 그림자 광선을
  통과시키지만, 렌즈는 서로 그림자를 드리워야 형상이 읽히기 때문입니다.
  투과율이 높고 그림자도 없으면 흰 필름 위의 흰 돔이라 **아예 보이지 않습니다**.
- **발광면 위치** — 발광 평면은 렌즈 어레이 **아래**(필름 상면)에 있습니다.
  빛이 렌즈를 통과해 나오므로, 렌즈 격자가 초록빛 위로 비쳐 보입니다.
- 유리 층은 그림자 광선을 통과시키는 Light Path 트릭이 걸려 있어, Cycles에서
  굴절 유리 아래가 검게 나오는 문제가 없습니다.
- 컬렉션: `Device conventional`, `Device design rule`, `Studio`, `Cameras`
  (카메라 3개: `Cam both`, `Cam conventional`, `Cam design rule`).

### 투명 배경 (기본값)

`--bg transparent` 가 기본이라 렌더는 **알파 채널이 있는 PNG**로 나옵니다.
바닥은 지워지지 않고 shadow catcher 로 바뀌므로, 배경은 비면서 접지 그림자는
남습니다. 회색 스튜디오 배경이 필요하면 `--bg studio`.

한 가지 주의할 점이 있어 컴포지터가 자동으로 붙습니다. Cycles 에서 옅은 발광
볼륨은 알파가 거의 0 이라, 투명 배경으로 렌더하면 **빛 안개가 RGB 에는 있는데
합성하면 사라집니다.** 그래서 컴포지터에서

- 알파 = `max(원래 알파, 채널 최댓값)` 로 다시 만들고,
- 원래 알파가 **거의 0 이던 곳(= 안개)만** 색을 un-premultiply 합니다.

두 번째 항목의 "거의 0"이 중요합니다. 그림자 캐처 픽셀은 알파가 0 이 아니라
0.3~0.6 정도인데, 이걸 안개로 오인해 un-premultiply 하면 그림자 색이 흰색 쪽으로
들려서 **소자 옆에 어색한 회색 쐐기**가 생깁니다. 그래서 마스크에
`alpha x 12 (clamp)` 를 걸어 부분 알파는 원본 색을 그대로 쓰게 했습니다.

휘도가 아니라 **채널 최댓값**을 쓰는 이유가 있습니다. 채도 높은 색을 휘도로
나누면 강한 채널이 1 을 넘겨 클리핑되면서 색이 흰색으로 돌아갑니다. 채널
최댓값으로 나누면 색조가 그대로 보존됩니다.

덕분에 밝은 배경에도 어두운 배경에도 초록빛이 그대로 얹힙니다.
이 처리가 싫으면 `Compositing` 노드 트리를 끄면 됩니다.

같은 노드 트리 맨 앞의 `Hue Saturation Value` 가 채도를 1.30 배 올립니다.
이 Blender 빌드는 OCIO 룩(`AgX - Punchy` 등)을 노출하지 않아서 직접 넣었습니다.
AgX 는 밝은 부분의 채도를 깎기 때문에, 발광 세기(`EMIT_STRENGTH`)를 올려
코어를 날리면 오히려 색이 흰색으로 빠집니다 — 색을 진하게 하고 싶으면
세기가 아니라 `GLOW` 와 이 채도 값을 조절하세요.

### 미감 관련 설정

- **모서리 베벨** — 모든 층 박스에 폭 0.0035 / 4 세그먼트 베벨이 걸려 있습니다.
  완벽하게 날카로운 모서리는 CG 티가 가장 많이 나는 요소입니다.
- **환경광은 옆으로 기운 그라디언트**입니다. 천정이 밝으면 위를 향한 렌즈 캡들이
  전부 같은 양의 빛을 받아 **배열의 음영이 통째로 사라집니다.** 실제로 이 문제로
  렌즈가 안 보였고, 환경광을 어둡게(0.11) 하고 좌우 방향으로 바꿔 해결했습니다.
- **렌즈 캡이 직접 발광합니다** (`lens_material`). 빛은 렌즈를 통과해 나오므로
  물리적으로도 맞고, 덕분에 캡을 거의 불투명하게(투과 0.08) 두어 음영을 살리면서도
  초록이 나옵니다. 발광 평면과 같은 `radial_falloff` 노드를 공유하므로 어긋나지
  않습니다. 비율은 `LENS_EMIT_FRAC`.
- **그림자는 하나만.** 키 라이트만 그림자를 만들고 필 / 림은 `use_shadow=False`
  입니다. 그리고 키를 거의 머리 위(z=12)에 두어 그림자가 소자 **아래로** 깔립니다.
  옆에서 비추면 화면을 가로지르는 긴 쐐기가 생겨 지저분해집니다.
- **키 라이트는 크고 부드럽게**(size 9). 작고 단단한 광원은 렌즈 어레이의 그림자를
  바닥에 빗살처럼 찍어냅니다.
- 카메라는 85 mm 로 멀리서 — 거의 정사영에 가까워 기술 도면 같은 깔끔함이 납니다.

렌더는 Cycles(CPU). 빌드에 OpenImageDenoise가 있으면 켜지고, 없으면
`denoise_renders.py` 로 외부 디노이즈합니다(PyPI `oidn`, `OpenEXR` 패키지;
빌더가 알베도·노멀 패스를 EXR로 같이 저장해 둡니다).

```bash
blender -b -P figures/build_emitting_area_blend.py -- --out figures                  # 씬 + 렌더 3장
blender -b -P figures/build_emitting_area_blend.py -- --out figures --no-render      # 씬만
blender -b -P figures/build_emitting_area_blend.py -- --out figures --bg studio      # 회색 배경
blender -b -P figures/build_emitting_area_blend.py -- --out . --quality test --cam conventional
python3 figures/denoise_renders.py figures/emitting_area_render*.png
```

`--cam` 은 이름 일부만 줘도 됩니다(`both`, `conventional`, `design`).
디노이저는 알파 채널도 같이 정리합니다 — 컴포지터가 글로우의 노이즈를
