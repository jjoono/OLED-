# 1. E_b — 지금 데이터의 신뢰도

## 1.1 실제 프로토콜 (scripts/05, 06)

```
방법   PBE-D3BJ / def2-SVP (Ag: def2-ECP), UKS 이중항, counterpoise 보정
기하   분자는 GFN2-xTB 최적화 구조로 고정(frozen). Ag만 움직임
탐색   결합축 1차원 강체 스캔, 최소점 근처 0.1 Å 간격 7점
       일부는 Ag 위치만 DFT로 재최적화(05) 후 측면 오프셋 스캔
```

**즉 "완전 최적화된 착물의 결합에너지"가 아닙니다.** 분자가 Ag를 만나 완화될 여지를
주지 않았으므로 **참값의 하한**입니다. 강한 결합자(HATCN, F4TCNQ)일수록 완화 이득이
클 테니, **실제 서열 격차는 표보다 더 벌어질 가능성이 높습니다.**

## 1.2 신뢰도 등급

### A등급 — 그대로 인용 가능
`HATCN(CN) 1.029` · `F4TCNQ 0.966` · `Cs2CO3 0.900` · `Bphen 0.490` ·
`Mo3O8 0.445` · `Al4O6 0.422` · `pyridine 0.342` · `triazine 0.291` ·
`BTD 0.277` · `Me3P=O 0.253` · `LiF32 0.249` · `thiophene 0.169` ·
`benzene 0.167` · 프래그먼트 10종

스캔 최소점이 격자 위에 있고(2.338, 2.541, 2.896처럼 비정수), 앵커가 확인됨.

### B등급 — 값은 쓰되 배위 모드는 미확정
`TPBi 0.889` · `p-bPPhenB 0.870`

`psi4_binding_refined_eV.json`의 `_offset` = 0.0 — 측면 오프셋 탐색에서
개선이 없었다는 뜻. 저장된 구조는 Ag가 **정확히 2.30 Å**에 있어, 이 파일만으로는
단좌/이좌를 판정할 수 없음. 이좌라는 감사 결과는 별도 전체최적화에서 나온 것.

### C등급 — 구조 자체가 비물리적, 재계산 필요
`p-bPPhenB 구조` (Ag–N **1.39 Å**) · `B3PyMPM 0.626` (Ag–H **1.85 Å**) ·
`Liq 0.167` (Ag–Li **0.91 Å**)

전부 결합거리가 아님. **초기 배치가 최적화 없이 그대로 남은 것.**
`pathgeom.sanity()`가 이제 이 구조들을 거부함(scripts/97, 102).
E_b 값 자체는 별도 스캔에서 나왔을 수 있으나 **구조와 값의 대응이 확인 안 됨.**

### 기각 — 표에 넣으면 안 됨
`Al2O3 0.910` (Al-rich Al10O10 과결합, 정량비는 0.422) ·
`MoO3 -0.718` (미정련, 정련값 +0.284) · `ZnS 1.60` (문헌 추정, 미계산) ·
`PhCN·ZnS 1.218` (ZnS–나이트릴, Ag 무관) · `HATCN face -0.207` (미정련, -0.024) ·
xTB 값 전부 (HATCN 3.08, TPBi 2.14 — DFT를 덮어쓴 전력 있음)

## 1.3 방법론적 한계 (A등급에도 해당)

| 한계 | 영향 | 서열에 영향? |
|---|---|---|
| 분자 고정(rigid) | 참값의 하한 | 거의 없음 (모두 동일 처리) |
| def2-SVP (이중제타) | CP 보정해도 ±0.1 eV 수준 | 작음 |
| PBE (GGA) | 전하이동계에서 비편재화 오차 | **강한 억셉터에서 과대평가 가능** |
| 이중항 가정 | Ag⁺/분자⁻ 전하이동 상태 미검토 | **미확인** |
| Ag 단원자 | 실제 임계핵은 Ag_n일 수 있음 | Venables 전제와는 일치 |
| 무기물은 소형 클러스터 | 표면이 아님 | **Al2O3 사례가 실증** |
| 단좌 vs 이좌 혼재 | 자리당 값이 아님 | **큼 — 반드시 분리** |

**가장 큰 위험은 GGA의 비편재화 오차입니다.** HATCN·F4TCNQ 같은 강한 억셉터에서
PBE가 전하이동을 과도하게 안정화시켜 E_b를 부풀렸을 수 있습니다.
**검증법: 상위 3~4종만 ωB97X-D 또는 M06-2X/def2-TZVP로 재계산.**
서열이 유지되면 전체 스크리닝이 방어됩니다.

## 1.4 논문에 쓸 때

- **절대값을 주장하지 말고 서열을 주장할 것.** 동일 프로토콜 내 상대비교는 견고함
- 단좌/이좌를 **같은 축에 세우지 말 것**
- E_b는 **자리당** 값이며, 핵생성을 정하는 것은 **자리밀도 × 결합**
  (scripts/111: HATCN 13.7 /nm², TPBi 2.1 /nm²)
- C등급 3종은 재계산 전까지 표에서 제외

# 2. E_d — 무엇을 어떻게 계산해야 하는가

## 2.1 현재 상태

| | 값 | 출처 |
|---|---|---|
| HATCN | 0.286 eV | scripts/24, DFT |
| Al4O6 (AlOx) | 0.170 eV | scripts/24, DFT |
| clean Al | 0.000 | 참조 |
| TAPC | −0.007 | 참조 (사실상 0) |

**나머지 16종은 미계산.** GFN2-xTB 스크린은 **기각** — DFT 값이 있는 두 계에서
모두 0.000 eV를 반환(0.286, 0.170 대비). scripts/101에 기록.

## 2.2 이 세션에서 잡은 프로토콜 버그 두 개

**① 경로가 분자를 관통했습니다.** 두 결합자리 사이를 직선 보간하면 중점에서 Ag가
기판 원자와 결합거리까지 접근 → 최대 **964 eV** 같은 값이 나왔습니다.
이제 매 스텝 표면 법선으로 밀어내 최근접 2.2 Å를 유지합니다(`pathgeom.place`).

**② 출발점만 높이 스캔에서 제외했습니다.** "이미 최적화된 구조"라는 논리였는데
DFT 기준으로만 최적입니다. 다른 방법에서는 출발점이 경로 최고점이 되어
**E_d가 정확히 0**으로 나옵니다. 이제 모든 점을 동일 처리합니다.

두 버그 모두 **원래 DFT 캠페인에도 있었습니다.** xTB 우회 시도가 이를 드러냈습니다.

## 2.3 현재 프로토콜의 근본적 한계

```
E_d = max(경로) − E(출발점)
경로 = 최근접 등가자리로 직선 드래그, 기판 고정, Ag 높이만 스캔
격자 = 경로점 3~5, 높이 2점  (4코어 제약으로 축소)
```

**이건 안장점 탐색이 아니라 성긴 강체 스캔입니다.** 얻는 값은 **하한** —
성긴 경로가 진짜 안장점을 놓칠 수는 있어도 없는 장벽을 만들지는 않습니다.

더 근본적으로 **고립 분자 하나 위의 확산장벽은 실제 막의 확산장벽이 아닙니다.**

- 자리가 **분자당 여러 개**인 경우(HATCN 6, F4TCNQ 4)만 분자내 hop이 물리적
- 자리가 **하나**면(pyridine, PhCN) 이동은 분자간이고, 그건 **패킹**이 정합니다
- 그래서 `site2site` / `toface` / `chelate` 세 class를 값과 함께 기록합니다.
  **class가 다른 값을 한 줄에 세우면 안 됩니다** — 단좌/이좌와 같은 문제

## 2.4 계산 수준의 사다리

| 등급 | 방법 | 비용 | 얻는 것 |
|---|---|---|---|
| **T1 (현재)** | 고립분자, 강체 드래그, 3~5점 | 시스템당 ~1 h (64코어) | class 내 **서열**. 절대값 신뢰 불가 |
| **T2** | 경로점 9~11 + 각 점에서 Ag 완전완화 | 5~10배 | 안장점 위치 개선. 여전히 고립분자 |
| **T3** | **NEB**, 분자 2~3개 클러스터로 막 표면 모사 | 30~50배 | 분자간 hop 포함. 실제 막에 근접 |
| **T4** | 주기적 슬랩 + NEB (VASP/CP2K) | 100배+ | 참값. `env/`에 cp2k 있음 |

**권장: T1으로 전 후보 서열을 잡고, 상위 3~4종만 T3로 검증.**
논문에는 T1을 "screening-level barrier, lower bound"로 명시하고
T3 결과를 상위 후보의 확증으로 씁니다.

## 2.5 실행 경로

- 스크립트 완성됨: `97_diffusion_barriers.py` (psi4), `102_ed_gaussian.py` (G16)
- 경로 생성은 `pathgeom.py`로 공유 — 두 드라이버가 갈라질 수 없음
- **4코어 컨테이너에서는 불가** (31원자 SCF 하나에 ~10분). 워크스테이션 64코어 필요
- Gaussian `SCF=(XQC)`가 psi4의 수렴 문제를 해결. pyridine에서 psi4와 **6 meV 일치** 확인
- 출력 분리(`GAUSS_OUT`) + 병합(`103_merge_Ed.py`)으로 4창 병렬 가능
- C등급 구조 3종은 자동 거부됨 → **재최적화 후 재투입 필요**

## 2.6 E_d 없이도 할 수 있는 것

E_d가 전 후보에 없어도 **자리밀도 × E_b**만으로 closure thickness 예측이 나옵니다
(scripts/111). E_d는 그 예측을 정교하게 만들 뿐 뒤집지 않습니다 —
Venables에서 E_d는 exp(χ·E_d/kT), χ=0.284이므로 **0.1 eV 차이가 3배**입니다.
따라서 **후보 간 E_d 차이가 0.1 eV를 넘으면 서열이 바뀔 수 있고,
그것이 E_d를 계산해야 하는 유일한 이유입니다.**

# 3. 우선순위

1. **C등급 3종 구조 재최적화** — 반나절. 안 하면 표에 못 씀
2. **E_d 전 후보 (T1)** — 워크스테이션 하룻밤
3. **상위 4종 E_b를 하이브리드 범함수로 재계산** — GGA 비편재화 오차 방어
4. **상위 3종 E_d를 T3 (NEB)로** — 논문의 메커니즘 절
5. 실험 검증: 시드 6종 closure thickness — **계산보다 이게 더 결정적**

# 부록: Gaussian 실행에서 확인된 것 (2026-09-10)

## 밀도적합은 쓰면 안 됨

벤젠 동일 구조, 동일 route에 `/Auto`만 추가한 대조:

| route | E (Hartree) | 사이클 | 시간 |
|---|---|---|---|
| 원본 `SCF=(XQC,MaxCycle=128)` | −378.729900502 | — | ~29 s (여유 머신) |
| `+VShift=300, MaxCycle=64` | −378.729900502 | 40 | 410 s (공유 머신) |
| `+/Auto` (밀도적합) | **−378.738217930** | 23 | 833 s |

- **VShift는 답을 바꾸지 않는다** — 원본과 소수점 9자리까지 동일. 수렴 경로만 바꾼다는 것이 실증됨
- **밀도적합은 답을 0.226 eV 바꾸고 2배 느리다.** 자동 생성 fitting set의 오차이며, 두 가지 이유 모두로 기각

psi4는 `scf_type df`를 썼으므로 두 프로그램 값의 직접 비교에는 이 차이가 잠재적 오차원이다.
다만 psi4의 DF는 최적화된 표준 auxiliary basis를 쓰고 Gaussian `/Auto`는 자동 생성이므로
동급이 아니다. **프로그램 간 비교는 HATCN 한 점으로만 하고, 나머지는 프로그램 내부 서열로 쓴다.**

## SCF 수렴 실태

Bphen (468 기저함수, Ag + 페난트롤린):

```
DIIS 129 사이클 → 수렴 실패, E = -1178.65242274
Quadratic Convergence SCF Method 전환
QC 7 사이클 → 수렴, E = -1178.68912812   (DIIS 값보다 1.0 eV 낮음)
S**2 = 0.7522 (이중항 이론값 0.75)
총 34분
```

- DIIS는 수렴 근처에도 못 갔고 ΔE 부호가 매 사이클 뒤집히는 전형적 진동
- **QC 자체는 7 사이클로 빠르다.** 비용은 앞의 129 사이클이 전부 버려지는 것
- 작은 분자(≤240 기저함수)는 DIIS가 정상 수렴 — 큰 분자에서만 발생

## 병렬 관련 (정정)

`Job cpu time ≈ Elapsed time`을 보고 단일 코어 실행을 의심했으나 **오진**.
작업관리자 CPU 100% 확인됨. G16W는 CPU 시간을 마스터 스레드 기준으로 찍는다.

**공유 머신에서는 `%NProcShared`를 실제 확보 가능한 코어 수로 낮추는 편이 빠르다.**
다른 사용자와 32코어를 다투면 스레드 전환 비용만 늘어난다.

## SCF 해의 불안정성 — 이 프로젝트의 가장 큰 방법론적 문제 (2026-09-10)

Bphen(468 기저함수)과 HATCN(444)에서 **DIIS가 수렴하지 않고 헤맵니다.**

동일 구조 Bphen을 세 번 돌린 DIIS 종점:
```
-1178.6525 (129 사이클)  /  -1178.7037 (65)  /  -1178.6325 (129)
폭 1.94 eV
```

HATCN은 사이클마다 ΔE가 **±0.36 eV**로 진동합니다. 128 사이클 후에도 진동 중.

세 경우 모두 Gaussian이 `Quadratic Convergence`로 전환한 뒤에야 수렴했고,
QC 결과는 DIIS 종점보다 **0.5~0.6 eV 낮습니다.**

### 결과적으로

1. **DIIS 계열 수렴(레벨시프트·댐핑 포함)은 이 계에서 신뢰할 수 없습니다.**
   psi4의 `ROB` 설정(level_shift 1.0 + damping 15%)도 DIIS 계열입니다.

2. **따라서 `runs/diffusion_barrier_eV.json`의 HATCN 0.286과 AlOx 0.170도
   검증 기준으로 쓸 수 없습니다.** 같은 약점을 가진 두 번째 측정일 뿐입니다.
   이 세션에서 psi4를 재실행했을 때도 −1487.24 근처에서 동일하게 진동했습니다.

3. **E_b 값들도 재검토 대상입니다.** 같은 프로토콜(psi4 + DIIS 계열)로 계산됐고,
   HATCN·F4TCNQ 같은 강한 억셉터가 정확히 이 문제가 생기는 계입니다.
   0.6 eV 규모의 해 차이는 E_b 서열을 바꿀 수 있습니다.

### 대응

- 확산장벽: `SCF=(QC,MaxCycle=64)` — DIIS 단계를 아예 건너뜀 (v4)
- 경로 전체를 `%Chk` + `Guess=Read`로 연결 — 모든 점을 같은 전자상태에 고정
- **E_b 상위 후보 재계산 시에도 QC를 써야 함.** 하이브리드 범함수 재계산
  (§1.3에서 권고한 것)을 할 때 함께 처리하면 한 번에 끝남

### 아직 모르는 것

QC가 찾는 해가 진짜 바닥상태인지는 `Stable=Opt`로 확인해야 알 수 있습니다.
변분적으로 더 낮으므로 DIIS 해보다는 낫지만, 그보다 더 낮은 해가 있을 가능성은
배제되지 않았습니다. 상위 3~4종에 대해서만이라도 안정성 검사를 권합니다.

## 수렴 기준 완화 (v5, 2026-09-10)

QC 전환으로 진동은 잡혔으나 **수렴 선언이 안 됩니다.**

HATCN_t0_z0, `SCF=(QC,MaxCycle=64)`:
```
반복 13  E = -1487.254882549   ΔE = -5.9 ueV   Grad = 5.369e-3
반복 18  E = -1487.254883215   ΔE = -2.9 ueV   Grad = 5.659e-3  ← 기울기가 상승
RMSU = 9.98e-08
```

에너지는 소수점 7자리까지 평평한데 **기울기가 오히려 올라갑니다.**
알파 HOMO-LUMO 간격이 0.008 Hartree(0.22 eV)라 궤도 공간이 거의 축퇴돼 있고,
**에너지를 바꾸지 않는 회전 방향**이 존재합니다. Gaussian은 그 기울기를 0으로
만들려 하지만 원리적으로 불가능합니다. 64 반복을 다 쓰고 실패로 기록됩니다.

### 판단 근거

- 로그의 RMSU가 이미 1e-7. Gaussian 기본값은 1e-8 요구
- 장벽 0.29 eV = 0.0107 Hartree. 1% 분해능에 필요한 것은 1e-4 Hartree
- 에너지는 1e-7 Hartree로 안정 → **세 자릿수 여유**

→ `Conver=6` (밀도 1e-6)로 완화. 이미 만족하는 수준이며 목적에 과분한 정밀도.

### 최종 설정

```
#P PBEPBE/Def2SVP EmpiricalDispersion=GD3BJ SP SCF=(QC,MaxCycle=64,Conver=6) NoSymm
%Chk=<folder>.chk   +   Guess=Read  (첫 작업 제외)
```

### 설정 변경 이력과 근거

| 버전 | 변경 | 근거 |
|---|---|---|
| v1 | `XQC,MaxCycle=128` | 초기값 |
| v2 | `+VShift=300, MaxCycle=64` | Bphen DIIS 128 사이클 낭비 |
| v3 | `+%Chk/Guess=Read` | **같은 구조가 0.51 eV 다른 해로 수렴** |
| v4 | `QC` (DIIS 제거) | DIIS 종점이 세 실행에서 1.94 eV 폭으로 산포 |
| v5 | `+Conver=6` | 축퇴로 기울기 수렴 불가, 에너지는 이미 1e-7 |

v1~v2 결과(Al4O6, benzene)는 궤도 연결이 없어 폐기.
