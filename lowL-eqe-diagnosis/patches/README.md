## 적용 순서

### 지금 바로 적용 가능 (벤치 테스트 결과와 무관)

**1. `photodiode_gain.json`** — 40/60 dB cutoff 가 실측 노이즈의 44~48배로 잘못 들어가 있고
모노토닉하지도 않았다(40 dB 300 uV > 50 dB 100 uV). 다른 항목과 같은 기준(실측 노이즈의 5 sigma)으로 고쳤다.

| Gain | 기존 | 수정 | 근거(실측 노이즈) |
|---|---|---|---|
| 40 dB | 3e-4 | **3e-5** | 6.8 uV x 5 |
| 60 dB | 4e-3 | **4e-4** | 83 uV x 5 |

50 dB(현재 유일한 실사용 gain) 값은 랩에서 2023-03-30 에 손으로 바꾼 `1e-4` 를 그대로 유지했다
(upstream 기본값은 `2e-4`). **파일을 통째로 덮어쓰기 전에 로컬 값이 정말 1e-4 인지 확인할 것.**
80 dB 항목은 저항값이 60 dB 보다 작게 적혀 있어 수상하지만, 근거 데이터가 없어 손대지 않았다.

**2. `hardware.py` 오타** — 로컬 사본에만 있는 문제라 diff 에 넣지 않았다. 직접 고칠 것:
```
self.spectrometerr.close()   ->   self.spectrometer.close()
```
`OceanSpectrometer.close_connection()` 안에 있다(로컬 477행 근처). 지금은 spectrometer close 가
항상 AttributeError 로 실패한다.

**앰프(PDA200C) 지배로 확정.** 결과:

- **레인지 전환(2-A)은 폐기.** ①②에서 예측한 값이 28.60 uV 였고 ③ 실측이 28 uV 로,

  TIA 교체로 노이즈가 내려간 뒤에는 레인지를 내리는 선택지가 살아 있다.
- **저잡음 TIA 교체가 유일한 하드웨어 레버.** 475 kOhm 의 Johnson 노이즈 한계(0.089 uV/sqrt(Hz))보다
  약 42배 위에 있고, PD 산탄노이즈는 완전히 무시 가능하다(1 cd/m2 신호 기준 0.04 pA).
  10~30배 개선 시 측정 시간은 sigma^2 에 비례하므로 100~900배 단축된다.
- **측정 시간 추정 상향**: 원 추정이 sigma = 20 uV 가정이었으므로 (28.62/20)^2 = 2.05배.
  1 cd/m2 +-2% 가 50초 -> 약 100초 (PD 거리 60 mm 적용 후 기준).
- **후속 테스트 추가**: 앰프 노이즈가 백색인지 1/f 드리프트가 섞였는지에 따라
  `baseline_period` 와 `samples_per_burst` 가 달라진다.
  `../bench_test/noise_test2_averaging.py` (테스트 ②와 같은 셋업, 물리 작업 없음, 약 3분).

### 벤치 테스트 4 (앰프 노이즈의 시간 구조) — 2026-08, 완료

`../bench_test/noise_test2_averaging.py`, 6000 샘플 / 149 s / 샘플당 24.9 ms.

```
sigma (1 샘플 전체 산포)      37.54 uV
sigma_chop (25 ms 인접 차분)  15.26 uV
sigma_chop 은 블록 1 ~ 500 샘플에서 13~15 uV 로 평평
그냥 평균: 12.4 초를 평균해도 37.5 -> 23.8 uV 밖에 안 내려감
```

**앰프 노이즈는 백색이 아니라 1/f 플리커다.** Allan deviation 이 평평한 것이 그 시그니처다.
전체 산포 37.54 uV 중 백색 성분은 ~15 uV 뿐이고 나머지는 저주파 드리프트다.
측정 밴드(25 ms ~ 12 s) 안에 백색 구간이 아예 없다 — 스크립트가 knee 를 0.12 s 로 찍었지만
실제로는 가장 짧은 시간부터 이미 드리프트 지배다(m=2 에서 벌써 1.35배).

세션 간 sigma 가 28.62 -> 37.54 uV 로 움직인 것도 같은 이유다. 재현되는 값은 sigma_chop 쪽이다.

파라미터 결정:

| 항목 | 기존 | 변경 | 근거 |
|---|---|---|---|
| `samples_per_burst` | 5 | **1** | sigma_chop 이 블록 크기에 무관하게 평평 -> 버스트를 늘려도 사이클당 오차가 안 줄어든다. 버스트를 줄이고 사이클 수를 늘리는 쪽이 이긴다(반복은 1/sqrt(N)). 약 4배 단축 |
| `baseline_period` | 5.0 | **0.0** | 드리프트가 25 ms 스케일에서 이미 지배 -> baseline 공유 불가. 원 계획의 "공유로 2배 단축" 취소 |
| `chop_pattern` | — | `"AB"` (기본) / `"ABBA"` 옵션 추가 | ABBA 는 off/on 의 시간 무게중심을 맞춰 드리프트의 선형 성분을 상쇄한다. 합성 데이터 검증에서 편향 +0.32% -> +0.08%. 실기기 검증은 아직 |
| `settle_time` | 0.02 | 실측 후 축소 권장 | 샘플 1개가 24.9 ms 인데 settle 20 ms 면 사이클의 45%가 대기다. OLED EL 응답은 ms 이하이므로 SMU 정착 시간만 실측해서 줄이면 된다 |

측정 시간 재추정 (사이클당 노이즈 = 15.26 x sqrt(2) = 21.6 uV, PD 거리 60 mm 적용 후):

| 휘도 | 목표 | 사이클 수 | settle 20 ms | settle 5 ms |
|---|---|---|---|---|
| 1 cd/m2 | +-2% | 729 | 65 s | 44 s |
| 1 cd/m2 | +-1% | 2916 | 262 s | 174 s |
| 3 cd/m2 | +-2% | 81 | 7 s | 5 s |
| >=10 cd/m2 | +-2% | min_cycles(16) | 1.4 s | 1.0 s |

현재 거리(167 mm, 1 cd/m2 에서 PD ~5 uV)로는 +-2% 에 46,656 사이클 = 약 70분이다.
**PD 거리 60 mm 재배치(3단계) 없이는 1 cd/m2 측정이 성립하지 않는다.**

### 벤치 테스트 5 / 6 (드리프트 출처) — 2026-08

**테스트 5 (PD 케이블 분리)**: 평균 93.8 uV, sigma 906.66 uV.

sigma 판정에는 **쓸 수 없는 데이터**다. TIA 입력을 개방하면 그 노드가 고임피던스 안테나가 돼서
주변 픽업을 다 받는다(37.5 -> 906 uV). 개방 입력은 "앰프 단독" 조건이 아니다.

하지만 **평균값이 결정적이다**:

```
PD 연결: 8198 ~ 8290 uV      PD 분리: 93.8 uV
-> 8.2 mV 오프셋은 전부 PD 에서 나온다 (앰프 자체 오프셋은 94 uV)
-> PD 정상 전류 = 8.2 mV / 475 kOhm = 17.3 nA
```

**테스트 6 (PD 재연결 + 수광면 직접 차폐)**: 평균 여전히 8.2 mV.
-> 차광 누설이 아니라 **PD 암전류**다.

17.3 nA / 0.75 cm2 = 23 nA/cm2 로, 역바이어스가 걸린 대면적(75 mm2) Si PD 의 전형값이다.
고장이 아니라 PD 가 크기 때문에 나오는 값이다.

이 시점의 잠정 결론은 "드리프트 = 암전류의 온도 의존성" 이었으나,
**아래 테스트 7 (gain 스윕) 에서 뒤집혔다.** 노이즈와 드리프트는 암전류와 무관하다.

또한 이 배경(8.2 mV)은 2026년 캘리브레이션 기준 약 1,200 cd/m2 상당으로,
재려는 1~10 cd/m2 신호의 100~1,000배다. 원인 (2) 가 왜 그렇게 치명적이었는지를 다시 확인해 준다.

### 벤치 테스트 7 (gain 스윕) — 2026-08, 완료

30 dB (R_f = 47.5 kOhm) 재측정. 전압을 R_f 로 나눠 앰프 입력단 기준 전류로 환산해 비교한다.

| | 50 dB (475 kOhm) | 30 dB (47.5 kOhm) | 비 |
|---|---|---|---|
| 평균 | 8.2 mV -> 17.3 nA | 10.1 mV -> 213 nA | 12.3x |
| sigma (1 샘플) | 28.6~37.5 uV -> 60~79 pA | 3.60 uV -> 76 pA | ~1x |
| sigma_chop (25 ms) | 15.26 uV -> **32 pA** | 1.71 uV -> **36 pA** | 1.1x |
| sigma_chop (12 s) | 13.02 uV -> **27 pA** | 1.14 uV -> **24 pA** | 0.9x |

**결론 1 — gain 은 레버가 아니다. 50 dB 유지 확정.**
입력환산 노이즈가 두 gain 에서 동일하다 = sigma 가 R_f 에 정확히 비례한다.
gain 을 어느 쪽으로 움직여도 SNR 은 변하지 않는다.

**결론 2 — 노이즈와 드리프트의 출처는 PD 가 아니라 앰프 입력단이다.**
암전류가 12.3배 늘었는데 노이즈는 1.1배만 늘었다(산탄노이즈라면 sqrt(12.3) = 3.5배여야 한다).
드리프트 바닥은 오히려 살짝 줄었다. 즉 둘 다 암전류와 무관하게 30 pA 근처에 고정돼 있다.
-> 테스트 5/6 의 "드리프트 = 암전류 온도 의존성" 잠정 결론을 철회한다.
-> 제로바이어스로 암전류를 줄여도 노이즈는 안 줄어든다. **저잡음 TIA 교체가 유일한 레버다.**

475 kOhm 의 Johnson 한계는 0.187 pA/sqrt(Hz)(약 1 pA 상당)이므로 현재 32 pA 는 약 32배 위다.
10~30배 개선 시 측정 시간은 sigma^2 에 비례해 100~900배 단축된다.

**오프셋이 gain 에 비례하지 않는 것(8.2 -> 10.1 mV)은 별개 문제다.**
PDA200C 가 gain 설정에 따라 PD 역바이어스를 함께 바꾸는 것으로 보인다(저gain = 고속용 = 고바이어스).
매뉴얼에서 gain 별 바이어스 사양을 확인하면 확정된다. 측정 계획에는 영향이 없다 —
오프셋은 chopping 이 매 사이클 제거하고, 노이즈는 위에서 본 대로 오프셋과 무관하다.
50 dB 쪽 암전류가 더 낮다는 것은 현재 설정이 이미 유리한 쪽이라는 뜻이다.

**TIA 발주 보류 해제.** 단, 발주 전에 아래 노이즈 밀도 분석의 확인 항목을 먼저 볼 것.

### 노이즈가 장비의 물리 한계인가 — 아니다 (29배 위)

```
측정      샘플당 15.26 uV (50 dB) -> 입력환산 32.1 pA
          NPLC 1 = 16.7 ms 적분 -> 등가잡음대역 1/(2T) = 30 Hz
          입력환산 밀도 = 5.9 pA/sqrt(Hz)   (출력환산 2.8 uV/sqrt(Hz))

물리 바닥  475 kOhm Johnson  0.187 pA/sqrt(Hz)
          17.3 nA 산탄노이즈 0.074 pA/sqrt(Hz)
          합계               0.20 pA/sqrt(Hz)

-> 29배 위. 측정 시간으로는 29^2 = 850배.
```

출력환산 2.8 uV/sqrt(Hz) 는 정밀 DC 계측 기준으로 높다(475 kOhm 자체 열잡음은 0.089 uV/sqrt(Hz)).
(장비명 정정: PDA200C 가 아니라 PDA100A2 다. 아래 데이터시트 대조 참조.)

다만 테스트 7 에서 노이즈가 R_f 에 정확히 비례했다는 것은 노이즈가 **게인단보다 앞(입력 노드)**
에서 들어온다는 뜻이고, 입력 노드에서 5.9 pA/sqrt(Hz) 는 잘 설계된 TIA 의 저주파 노이즈치고
너무 크다(보통 fA~pA). 장비 설계 한계일 수도 있지만 입력 노드가 무언가를 줍고 있을 수도 있다.
후자면 무료로 고쳐진다.

| 1 | PDA200C 매뉴얼의 50 dB NEP / 출력 노이즈 스펙 | 5분 | 실측 2.8 uV/sqrt(Hz) 와 일치하면 장비 한계 확정 -> 교체. 스펙보다 훨씬 나쁘면 셋업 문제 |

**2번 결과 (2026-08): SMU 를 끄고 재측정했으나 변화 없음.** 접지 루프 아님.

### 노이즈 조사 종료 — 결론

배제된 후보:

| 후보 | 배제 근거 |
|---|---|
| DMM | 테스트 1 — 1.02 uV (분산의 0.13%) |
| DMM 레인지 | 테스트 3 — 28.62 -> 28 uV |
| gain 설정 | 테스트 7 — 입력환산 32/36 pA 로 동일 |
| PD 암전류/바이어스 | 테스트 7 — 암전류 12배 변화에 노이즈 1.1배 |
| SMU / 접지 루프 | SMU off 재측정 — 변화 없음 |

남은 것은 앰프 입력단이다. 성분을 나누면:

```
백색   8 uV (17 pA)  <- 평균하면 1/sqrt(N) 로 감소
1/f   13 uV (27 pA)  <- 0.04 Hz 이하. 12초를 평균해도 그대로
```

지배적인 것은 27 pA 의 초저주파 드리프트다. 암전류/gain/SMU 와 모두 무관하다는 조건을
만족하는 것은 **앰프 입력단의 열적 드리프트**(입력 바이어스 전류의 온도 의존성)뿐이다.
JFET 입력 op-amp 의 바이어스 전류는 10도마다 2배로 변하므로 100 pA 대 바이어스가 25% 흔들리면
25 pA 다. 관측값과 맞는다.

더 파고들려면 PD 자리에 등가 커패시터를 넣는 정식 널 테스트가 필요하지만, 부품이 필요하고
얻는 것은 "역시 앰프였다"는 확인뿐이다. **수확체감이므로 조사를 종료한다.**
그리고 이 드리프트는 chopping 이 제거한다 — 원래 그러라고 만든 것이다.

### TIA 는 필수에서 편의로

PD 52 mm + chopping 기준 현재 도달 가능한 성능:

| 휘도 | +-2% | TIA 10배 개선 후 |
|---|---|---|
| 1 cd/m2 | 40초 (settle 5 ms 면 26초) | 0.4초 |
| 3 cd/m2 | 5~7초 | <1초 |
| 10 cd/m2 이상 | 1~2초 | <1초 |
| 6포인트 스캔 | 약 1분 | 몇 초 |

픽셀 하나에 1분이면 논문용으로 깨끗한 픽셀 몇 개를 정밀 측정하는 용도로는 충분하다.
측정할 픽셀 수가 많거나 +-1% 가 필요하면(지금 160초 -> 4초) TIA 가 값어치를 한다.
연구 계획에 달린 판단이다.

   넣는 것만으로 개선될 수 있다.
2. **데이터시트 확인** — 완료. 아래 참조.

### 데이터시트 대조 — 장비명 정정 + 실측이 스펙과 일치

**장비는 PDA200C 가 아니라 Thorlabs PDA100A2 다.** 초기 분석의 장비명이 틀렸다.

| | PDA200C | PDA100A2 | 랩 설정 |
|---|---|---|---|
| 게인 방식 | 전류 레인지(100 nA~10 mA) | 10 dB 8단계 | 10 dB 8단계 |
| 트랜스임피던스 | — | 1.51 kV/A ~ 4.75 MV/A | 1510 Ohm ~ 4.75 MOhm |
| 수광면적 | (외부 PD) | 75.4 mm2 (D9.8 mm) | 75 mm2 |

photodiode_gain.json 의 저항표와 PD 면적이 PDA100A2 와 완전히 일치한다.
PDA100A2 는 **PD 와 앰프가 한 하우징에 통합**된 제품이라 PD 만 교체하거나 바이어스를
조정할 수 없다 (테스트 8 이 애초에 불가능했던 이유이기도 하다).

**노이즈는 스펙과 일치한다.** NEP 2.67 ~ 71.7 pW/sqrt(Hz), 피크 응답도 0.72 A/W.
양 끝값 로그 보간(10 dB 당 0.625배) 기준:

```
50 dB NEP ~ 6.8 pW/sqrt(Hz) -> 입력환산 6.8e-12 x 0.72 = 4.9 pA/sqrt(Hz)
실측                                                    = 5.9 pA/sqrt(Hz)
-> 20% 안에서 일치
```

검출기는 스펙대로 정상 동작 중이고 우리는 이 장비의 설계 한계에 있다.
셋업 문제가 아니다. 노이즈 조사를 종료한 판단이 맞았다.
(보간값이므로 정확한 게인별 NEP 표는 매뉴얼에서 확인할 것.)

### 테스트 9 — 게인을 올리는 것이 공짜 개선일 수 있다

데이터시트 NEP 는 **게인이 높을수록 좋아진다**:

| Gain | NEP (보간) | 입력환산 | 50 dB 대비 | 측정시간 |
|---|---|---|---|---|
| 50 dB | 6.8 pW/sqrt(Hz) | 4.9 pA/sqrt(Hz) | 1x | 40초 |
| 60 dB | 4.3 pW/sqrt(Hz) | 3.1 pA/sqrt(Hz) | 1.6배 개선 | 16초 |
| 70 dB | 2.67 pW/sqrt(Hz) | 1.9 pA/sqrt(Hz) | 2.5배 개선 | 7초 |

**이것은 원 진단(README.md)의 "70 dB 는 손해, gain 전환 로직 넣지 말 것" 과 반대다.**
그 결론은 아카이브 eval 파일에서 역산한 값(70 dB 245 uV)에 기반했고, 데이터시트는 반대로 말한다.
어느 쪽이 맞는지는 직접 재면 6분에 갈린다.

포화 여유도 충분하다: 70 dB 에서 암전류 17.3 nA x 4.75 MOhm = 82 mV,
1 cd/m2 신호 520 uV, 포화 시작은 약 4,000 cd/m2.

**방법**: 검출기 게인을 60 dB, 70 dB 로 놓고 각각 noise_test2_averaging.py 실행.
sigma 를 R_f 로 나눠 입력환산으로 50 dB 의 32 pA 와 비교한다.
데이터시트대로면 70 dB 에서 13 pA 근처가 나와야 한다.

**결과 (2026-08): 개선 없음. 70 dB 실측 -> 입력환산 35.6 pA.**

| Gain | R_f | sigma_chop(1샘플) | 입력환산 |
|---|---|---|---|
| 30 dB | 47.5 kOhm | 1.71 uV | 36 pA |
| 50 dB | 475 kOhm | 15.26 uV | 32 pA |
| 70 dB | 4.75 MOhm | 168.87 uV | 35.6 pA |

R_f 를 100배 범위로 흔들었는데 입력환산 노이즈가 32~36 pA 로 고정이다.
데이터시트 NEP 보간에서 예측한 13 pA 는 나오지 않았다.

**NEP 보간 예측이 틀렸고 원 진단(README.md)이 맞았다.** NEP 스펙은 각 게인의 전대역
(70 dB 에서 3 kHz, 50 dB 에서 수십 kHz) 기준으로 보이며, 30 Hz 대역만 쓰는 DC 측정에는
그대로 적용되지 않는다. 아카이브 eval 파일에서 역산한 값이 실제 동작을 더 잘 반영했다.

-> **50 dB 유지 확정. 게인 전환 로직은 넣지 않는다.** 원 진단의 결론 그대로다.

### DC 오프셋은 암전류가 아니다 (앞선 해석 철회)

```
30 dB: +10.1 mV -> +213 nA
50 dB:  +8.2 mV ->  +17.3 nA
70 dB: -17.4 mV ->   -3.65 nA   <- 부호까지 뒤집힘
```

단일한 물리적 전류라면 이렇게 될 수 없다. **게인 레인지마다 다른 앰프 오프셋**이다.
테스트 5/6 에서 "8.2 mV = 암전류 17.3 nA" 로 읽었던 해석을 철회한다
(30 dB 결과에서 이미 어긋났던 부분이다). chopping 이 매 사이클 제거하므로 측정에는 영향이 없다.

### 적용

**3. `hardware.diff`** — `git apply hardware.diff` (OLED-jvl-measurement 루트에서). 내용:

- `KeithleyMultimeter.set_fixed_range` / `set_auto_range` **주석 해제 + 문법 수정**.
  원래 주석 코드는 `CONF:VOLTage:DC:RANGe <v>` 를 썼는데 2100 에서 유효하지 않다.
  `SENSe:VOLTage:DC:RANGe <v>` 로 바꿨다(이걸 쓰면 auto range 는 자동으로 꺼진다).
  → 벤치 테스트가 **DMM 지배**로 나올 때 쓰는 무비용 개선(2-A).
- `KeithleyMultimeter.configure_burst` / `read_burst` **신규**.
  `CONFigure` 1회 + `SAMPle:COUNt N` + `READ?` 로 한 번에 N 샘플을 받는다.
  기존 `measure_voltage()` 는 호출마다 `MEASure?` 를 보내 기기를 재설정하므로 chopped 스캔에 쓸 수 없다.
- `KeithleySource.set_low_light_mode(on)` **신규** — 5단계. 저휘도 모드에서만
  `Current:AZero ON` + 전류 NPLC 10, 종료 시 원복. 이걸 빼면 PD 를 고쳐놔도 분모(전류)가 EQE 오차를 지배한다.

**4. `chopped_measurement.py`** — `src/` 에 복사. `hardware.diff` 가 먼저 적용돼 있어야 한다.
기존 `AutotubeMeasurement`(일반 JVL 스캔)은 건드리지 않는다.

- 포인트마다 `V_target(settle -> 버스트) / 0 V(settle -> 버스트)` 를 반복하고 `dPD = mean(on) - mean(off)`
  → background 를 매 사이클 다시 재므로 **원인 (2) 계통 오프셋이 구조적으로 소멸**
- 반복 평균으로 **원인 (1) 랜덤 노이즈가 sqrt(N) 으로 감소**
- **N 고정이 아니라 수렴 조건**: `sigma/dPD <= target_relative_sigma` (기본 0.02 = +-2%).
  밝은 포인트는 자동으로 몇 사이클 만에 끝난다.
- **baseline 공유**: `baseline_period` 초마다 한 번만 off 를 재고 인접 사이클이 공유 → 약 2배 단축.
  드리프트가 의심되면 `baseline_period=0` 으로 두면 매 사이클 측정한다(가장 안전, 2배 느림).
- 포인트별 **sigma 를 파일에 같이 저장**(`Photodiode Voltage Sigma` 컬럼).

불확실도 계산은 baseline 공유 여부에 따라 자동으로 맞게 처리한다(`ChoppedSweep._combine`):
같은 baseline 을 쓴 사이클들을 한 그룹으로 묶고 **그룹 평균들의 산포**로 sigma 를 낸다.
전체 delta 의 std/sqrt(N) 을 그대로 쓰면 공유 baseline 오차를 과소평가하고,
baseline 오차를 따로 더하면 매 사이클 재측정하는 경우 같은 오차를 두 번 세게 되기 때문이다.

하드웨어 없이 로직 확인:
```
python chopped_measurement.py --simulate
```
가짜 DMM(신호 + 20 uV 노이즈 + 앰프 DC 오프셋)으로 수렴 동작과 통계를 검증한다.
1 cd/m2 (PD 40 uV) 포인트가 +-2% 에 231 사이클 = 실기기 기준 약 55초로 수렴하며,
이는 `../README.md` §8 의 시간 추정과 일치한다.

GUI 에 붙일 때는 `LowLuminanceMeasurement` (QThread 래퍼) 를 쓰면 되고,
`measurement_parameters` 에 다음 키가 필요하다:
`voltages`, `scan_compliance`, `samples_per_burst`, `settle_time`, `multimeter_range`,
`target_relative_sigma`, `baseline_period`.

`multimeter_range` 는 **10 (V) 로 둔다**. 2026-08 벤치 테스트에서 노이즈가 앰프 지배로 확정됐다
(아래 참조). 저잡음 TIA 로 교체한 뒤에 다시 판단할 것.

**5. `evaluation_functions.diff`** — `git apply evaluation_functions.diff` (OLED-evaluation 루트에서).

`JVLData.__init__` 의 cutoff 처리를 바꾼다. **기존 일반 스캔 동작은 그대로**이고,
데이터에 `pd_voltage_std` 컬럼이 있을 때(= chopped 스캔)만 다르게 동작한다:

```
pd_cutoff 적용 안 함  ->  dPD < 3 sigma 인 포인트만 NaN
```

핵심은 **0 과 NaN 의 구분**이다.
- `0` = "빛이 없다" (물리적 결론)
- `NaN` = "이 포인트는 측정 불가" (정보 없음)

기존 cutoff 는 후자를 전자로 기록해서, 최근 소자 기준 약 30 cd/m2 이하가 통째로
`L=0.00 / EQE=0.00` 으로 남는 원인이었다.

`sigma_threshold` 는 생성자 인자(기본 3.0)라 호출부 수정 없이 그대로 쓸 수 있다.

## 로컬 사본과의 차이 (적용 전 확인)

랩 로컬 사본은 upstream 과 최소한 아래가 다르다. diff 가 깨지면 이것부터 의심할 것.

- `hardware.py` 의 `spectrometerr` 오타 (upstream 에는 없음)
- `photodiode_gain.json` 의 50 dB cutoff `1e-4` (upstream `2e-4`)
- 진단 문서의 행 번호는 로컬 사본 기준이라 upstream 과 2~3행 어긋난다

diff 가 적용되지 않으면 `git apply --3way` 또는 해당 함수를 손으로 옮겨 넣으면 된다.
바꾸는 부분이 함수 단위로 독립적이라 수동 이식도 어렵지 않다.

## 이 패치들이 하지 않는 것

- **PD 거리 167 -> 60 mm (3단계)**: 하드웨어 작업 + 거리 재보정이라 코드로 대체 불가.
  chopped 스캔만으로도 오차는 줄지만, 거리를 줄여 신호를 7.7배 키우기 전에는
  1 cd/m2 에서 필요한 사이클 수가 수십 배로 늘어난다.
- **PD gain 전환**: 50 dB 고정 유지. 70 dB 는 신호 10배 대비 노이즈 12배(실측 245 uV)로 손해다.
- **일반 JVL 스캔 변경**: 그대로 둔다. 위 변경은 전부 저휘도 전용 경로에만 적용된다.
